# 📚 Document AI

A Streamlit chat app that lets you upload **PDF, Word (.docx) and TXT** files and ask questions about them. Answers are generated by Google Gemini using **only** the content of your documents, with file and page citations.

## Features

- **Multi-file upload** – PDF, DOCX and TXT, several files at once.
- **Grounded answers** – the model may only use retrieved context. If the answer isn't there, it replies: *"I don't know based on the uploaded documents."*
- **Citations** – facts are cited like `(file.pdf, p.3)` or `(file.docx)`, and an expandable **Sources** box shows the supporting snippets.
- **Follow-up questions** – pronouns and references ("it", "that section") are rewritten into standalone questions using recent chat history before searching.
- **Diverse retrieval** – MMR search returns relevant chunks without near-duplicate overlap text.
- **Careful file handling**
  - PDF: page numbers preserved (1-indexed); blank pages skipped.
  - DOCX: paragraphs, headings and tables kept in their original order.
  - TXT: tries UTF-8 (with BOM), UTF-16, CP1252, then Latin-1.
  - Scanned/empty files are skipped with a warning; old `.doc` files ask you to save as `.docx`.

## How it works

```
Upload → Load → Split → Embed → FAISS index
                                    │
Question → Rewrite follow-up → MMR retrieve → Gemini answer + sources
```

| Step | Details |
|------|---------|
| Split | `RecursiveCharacterTextSplitter`, chunk size 1000, overlap 200 |
| Embeddings | `gemini-embedding-2-preview` |
| Vector store | FAISS (in memory) |
| Retriever | MMR, `k=6`, `fetch_k=20`, `lambda_mult=0.7` |
| LLM | `gemini-3.6-flash`, `temperature=0` |
| History | Last 6 messages, each trimmed to 500 characters, used for question rewriting |

## Project structure

```
.
├── app.py            # Streamlit UI: upload, processing, chat, sources display
├── loaders.py        # PDF / DOCX / TXT loaders and the upload entry point
├── rag.py            # Models, prompts, FAISS index, RAGChain (condense → retrieve → answer)
├── requirements.txt  # Python dependencies
└── .env              # Your API key (you create this)
```

### `app.py`
Loads the API key, builds the page and sidebar, processes uploaded files into chunks, creates the RAG chain, stores state in `st.session_state`, and renders the chat with a Sources expander per answer.

### `loaders.py`
Exposes `SUPPORTED_TYPES` and `load_uploaded_file(uploaded_file)`. Each upload is written to a temporary file, parsed by the matching loader, and the temp file is always deleted. Every returned `Document` has `metadata["source"]` set to the original filename (PDFs also get `page`).

### `rag.py`
Defines the embedding model, the LLM, the answer and condense prompts, and the `RAGChain` class. `create_rag_chain(chunks)` builds the FAISS index and returns a ready chain. `RAGChain.invoke(question, history)` returns `{"answer": ..., "sources": [...]}`.

## Setup

1. **Python 3.10+** is recommended.

2. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   ```

3. **Add your Gemini API key.** Create a file named `.env` in the project folder (next to `app.py`):
   ```env
   GOOGLE_API_KEY=your_api_key_here
   ```
   `GEMINI_API_KEY` also works. Get a key from [Google AI Studio](https://aistudio.google.com/). Note the file must be named exactly `.env`, not `_env`.

4. **Run the app**
   ```bash
   streamlit run app.py
   ```

## Usage

1. Upload one or more files in the sidebar.
2. Click **🚀 Process Documents** and wait for the "Documents Ready" status.
3. Ask questions in the chat box. Open **📎 Sources** under an answer to see where it came from.
4. Use **🗑️ Clear Conversation** to reset the chat. Processing new documents also resets it.

## Limitations

- The FAISS index lives in memory only, so it is rebuilt each time you process documents and lost when the session ends.
- Scanned or image-only PDFs have no extractable text and are skipped (no OCR).
- Legacy `.doc` files are not supported; convert them to `.docx`.
- Only the last 6 chat messages are used to resolve follow-up questions.
- Model names (`gemini-embedding-2-preview`, `gemini-3.6-flash`) are set at the top of `rag.py`; change them there if your account uses different ones.
